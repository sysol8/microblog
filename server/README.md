# Microblog [backend]

Серверная часть приложения Microblog

## Архитектура

Приложение использует модульный подход, стандартный для приложений на Nest.js. Каждая сущность/фича выделена в отдельный модуль. Какие-либо переиспользуемые фрагменты кода (декораторы, типы и т. д.) вынесены в папку `\src\common`
На текущий момент приложение состоит из следующих модулей:

- Авторизация и аутентификация - `auth`;
- Пользователи - `users`;
- Посты - `posts`;
- База данных - `prisma`.

Модули содержатся в папке `modules`. Каждый модуль минимально состоит из сервиса (`*.service.ts`), контроллера (`*.controller.ts`) и точки входа (`*.module.ts`).

Помимо этого модули содержат:

- DTO, описывающие API-контракты. DTO служат для валидации входящих и исходящих данных в контроллере, а также для описания схем в Swagger;
- Селекты (файлы типа `*.selects.ts`). Селекты являются источниками правды и определяют, какие данные из БД будут вытянуты и отправлены в необходимые сервисы. Селектами оперируют соответствующие сервисы, а исходящие из этих селектов типы доступны в рамках всего приложения, что позволяет избежать внедрения лишних зависимостей;
- Декораторы для более удобной работы с сущностями.

## Переменные окружения
Проект может содержать значительное количество чувствительной информации, поэтому важной его частью является работа с переменными окружения.
Все переменные можно разделить на следующие группы (по префиксам):
- `HASH` - настройки, используемые для хеширования в сервисе работы с паролями;
- `S3` - секретные данные для работы с S3-совместимым хранилищем;
- `POSTGRES`, `DATABASE` - данные, связанные с БД;
- `AUTH`, `CSRF_COOKIE_NAME`, `SECURE_COOKIES` используются для настройки авторизационных куки;
- `AWS` - дополнительная группа переменных для работы с другими AWS-сервисами, кроме S3.

Все переменные окружения валидируются при помощи библиотеки zod.

## Запуск
### Подготовка
Для корректной работы приложения в папке `\server` нужно создать файл `.env`. Необходимые переменные окружения для запуска приложения указаны в `.env.example` и описаны в документации ранее.
